## Core algorithm (§2 of the final report)
`Cc<T>`/`CcBox{meta, value: ManuallyDrop<T>}` (`repr(C)`, meta at offset 0 for type-erased access; per-type static vtable {trace, drop_value, dealloc}). Strong counts; `Color{Black,Purple,Gray,White}`; `buffered` dedup flag; `freed` exactly-once value flag. Decrement-to-zero enters a DESTRUCTION TRAMPOLINE (thread-local queue + pump flag → all teardown iterative). Decrement-to-nonzero buffers once (Purple on first buffering). `collect_cycles()`: purge (dealloc parked freed entries, discard re-blackened) → PRE-VALIDATION (read-only borrow-check walk over candidate-reachable set — a failed `try_borrow` aborts with ZERO mutation) → iterative mark_gray (trial subtraction, one dec per edge) → iterative scan/scan_black (externally-referenced restore) → white gather → destruction: EDGE-RESTORE (undo trial subtraction for all white-originating edges) + VEC-GUARD (+1/white) + freed-first + value drops (cascades pump flat) + guard release through the uniform queue. Two deliberate deviations, both documented in-code: (1) fallible `Trace` (borrow-abort support); (2) clone does NOT re-blacken (Bacon–Rajan's blacken-on-increment is candidate pruning, not soundness; trades bounded re-trial work for a count-only clone hot path).

## Collector invariants (§3)
Omission safety is ARITHMETIC, not policy: an untraced (opaque) edge is a real `Cc` clone contributing +1 that trial deletion never subtracts → residual > 0 → scan_black restores → leak-only, premature-free impossible (proofs p19/p20 + property law 1 over generated omission graphs). Duplicate-edge = over-subtraction hazard → debug per-object detector, keyed on HANDLE address (two distinct handles to one target are two legitimate edges — a contract nuance the detector itself surfaced during development). Exactly-once destruction via freed flag + trampoline (proofs, law 4). No finalizers/resurrection/weak/guest-visible state. No collector re-entry from Drop (pump flag). All phases iterative.
