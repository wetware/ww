## 2. Three-domain value model

### The split, tested against current Glia

The three-domain split is coherent with current Glia and Wetware goals, and — the load-bearing observation — **current `Val` equality already implements it**: structural equality for exactly the durable-eligible variants, pointer/instance identity for exactly the executable ones (`lib.rs:538` — `Fn`/`Macro` by env ptr, `NativeFn`/`AsyncNativeFn` by fn ptr, `Cap` by minted id, `Atom` by cell ptr; everything else structural). The runtime has been carrying the domain boundary implicitly in its identity model all along.

**Domain assignment of current `Val` variants (18):**

| Domain | Variants | Notes |
|---|---|---|
| **A — local executable** | `Fn`, `Macro`, `NativeFn`, `AsyncNativeFn`, `Cap`, `Atom` | identity-compared; possibly authority-bearing; never serialized. PR-1b.0 adds `Defs` and `CapturedEnv` (not `Val`s, but A-domain objects). Handler stacks, continuations, resume fns (`NativeFn`s), effect machinery: A. |
| **B — durable content-addressed** | `Nil`, `Bool`, `Int`, `Str`, `Sym`, `Keyword`, `Bytes` | structurally compared; canonical-encodable. `Float` is B *pending* PR-2's canonical NaN/encoding decision (already on the PR-2 slate). |
| **Polymorphic (domain = transitive contents)** | `List`, `Vector`, `Map`, `Set` | B iff every element is B; A-contaminated otherwise. This polymorphism is the central design fact: **durability in Glia is a predicate/certification over values, not a type** — same shape as cap-freeness, and the same shape as Monte's DeepFrozen (batch 4, M-3). |
| **C — external references/specs** | none yet | today spelled as strings (module paths through `ModuleLoader`) or tagged maps (PR-0 cell tagged data). C-values are *structurally domain B* (plain durable data) and special only by interpretation: a CID, a durable callable spec, an effect requirement, an authority parameter. A live `Cap` is A; its *description* is C. |

**Ambiguous variants, resolved:** `Atom` — A by identity/mutability even when contents are B (an atom is a place, not a value). `Bytes` — B (the doc comment at `lib.rs:419` already says "produced by `(ipfs cat ...)`" — the durable plane's first tendril; note eager materialization, see §8 workload 1). `Sym` — B (data); its analyzer meaning is contextual, not intrinsic. Collections — polymorphic as above; no variant is intrinsically ambiguous once "domain = transitive contents" is accepted for containers.

**Guest-visible boundaries:** eventually, only B-vs-not-B must be guest-visible, and only at durability operations (persist/hash/send/spec-construction) as a *catchable exception* when certification fails — exactly Monte's guard-failure shape. Domain C needs no visibility mechanism: C-values are ordinary durable data. A-vs-B needs no visibility during normal evaluation (mixing domains in local collections is legal and routine). For PR-1b.0: entirely internal.

**Is `Val` too monolithic?** No — for stage one the split is a classification enforced at boundaries, which `Val` supports today (identity model already aligned; equality/hash never crosses domains). It becomes structural exactly twice, both already-scheduled seams: PR-2 collections (per-node summary bits: contains-A / durable-certified — the CHAMP rebuild is the natural place) and the future durable plane (an opaque handle variant for lazy CID-backed data, §4 rule 1).

**Existing decisions checked against the split — no violations:** exceptions-as-effects (control, orthogonal); frozen snapshot exports (A-domain maps, correct); per-import instantiation (A-domain instances of B-domain sources — the cache audit's source-text-only policy B is *exactly* the A/B split applied to modules: source text is B, instances are A); live capability analysis (authority = possession, discovered by analysis — matches "B is authority-free unless it contains an explicit C reference"). One *gap*, not violation: `(ipfs cat ...)` eagerly materializes content as `Bytes` — fine for small content, and the future lazy path must be a handle, never a transparent collection (§4).

## 3. Durable-callable analysis

The six-way distinction holds cleanly in Glia terms: **source form** (B: text/`Bytes`/CID), **analyzed code artifact** (B *only after* macro staging is fixed — code identity must be post-expansion canonical form pinned to a prelude/macro version; today analysis is interleaved with evaluation, so canonical analyzed artifacts are FUTURE work gated on the parked macro-staging fix), **module+entrypoint reference** (C: `{module-cid, entry}`), **durable callable spec** (C: the candidate rule's object), **live closure** (A: `Val::Fn` with `CapturedEnv` + owner), **remote capability** (C-described, A-instantiated as `Cap`).

**The candidate rule is correct and adopted as the working definition:**

> A callable is durably representable only when its code identity is stable and every captured dependency is durable data (B), a durable code/module reference (C), or an explicit external capability/effect requirement (C).

Answers:
1. **Arbitrary live closures cannot be serialized safely.** Captures may include `NativeFn`/`AsyncNativeFn` (process-local Rust pointers), `Cap` (live authority — serializing it would mint authority from data), `Atom` (identity + mutation — serialization forks the cell), and the owner reference itself (process-local `Defs` identity). BEAM is the precedent that even mature VMs refuse general closure serialization: funs cross nodes as module+id+free-vars references, not as code (agent 3 confirms).
2. **Disqualifying captures:** any domain-A value — `Cap`, `NativeFn`, `AsyncNativeFn`, `Atom`, a live closure whose own captures disqualify, and the implicit owner edge (must be replaced by a module CID in the spec). Also: dependence on a non-frozen `Defs` (late-bound names in a still-open module have no stable meaning).
3. **Durable specs are ordinary durable data** — a tagged map, no new `Val` variant, no special memory treatment. They are inert until a local runtime *instantiates* them (fetch module by CID → import machinery → bind captures → grant authority per requirements). Instantiation, not deserialization, is where A-domain objects appear.
4. **Spec fields — all six proposed fields are right**: module CID; entrypoint; durable captures (B/C only, enforced by certification); runtime/ABI contract (Glia semantic version + prelude CID — pins builtins and macro expansion); required effects (names + shapes); authority parameters (C descriptors the instantiator resolves to live caps).
5. **The effect system is the rebinding mechanism** — this is the deepest alignment found by this study. B3 already made import an effectful operation whose authority comes from the importer; durable callables generalize it: authority and nondeterminism travel as *requirements*; the local handler stack and cap grants satisfy them at instantiation. No closure serialization pressure remains for the authority-bearing part (see §9 rule).
6. **Handlers stay local and unserialized** — they are closures over local authority, definitionally A. A "durable handler" is just a durable callable spec that the local side instantiates *and then installs*.
7. **Determinism pinning:** canonical post-expansion code (gated on macro staging) + module graph by CIDs + runtime/ABI version + prelude CID (builtins + macros) + fuel policy as an explicit effect/parameter + all remaining nondeterminism (time, random, IO) as effects satisfied by the instantiator's handlers. Deterministic replay = same spec + same effect transcript.
8. **PR-1b.0 impact: none in scope, four seams to preserve** (see §7 audit and §11): keep `Defs` pure (bindings + inherited + frozen — no loader/host state embedded, already true); keep exports as plain maps (already durable-shaped); keep owner references private so a spec can substitute module-ref for owner; never expose local pointer identity as durable identity.
9. Everything else here is FUTURE (`doc/designs/portable-callables.md` draft in §13).

## 4. Normative Graph 4 jurisdiction

**Normative scope statement (adopted):**

> Amended Graph 4 governs only local executable value graphs (domain A and A-contaminated containers). Its transforms recurse **only** into the four transparent containers (`List`, `Vector`, `Map`, `Set`) and act **only** on owner references of A-domain values whose owner witness matches. Every other variant — all of domain B, atoms (opaque interior), sealed cap inners, host payloads, and any future durable handle — is **barrier-inert**: a leaf contributing O(1). Durable content-addressed graphs contain no owner-bearing values by certification and therefore bypass rest/escape entirely. Local owner management must never traverse the transitive contents of a durable or lazily-backed graph; lazy/CID-backed data may enter the local runtime only as an opaque handle, never as a transparent container.

Tested against the four examples:
- `{:handler live-closure :config durable-handle}` — local A-contaminated map: barrier walks 3 nodes; the handle is a leaf. O(local structure).
- CID → 10⁷–10⁹-node DAG — never enters the barrier: as a handle it is a leaf; the DAG lives behind it. (Today's gap: `ipfs cat` materializes eagerly as `Bytes` — `Bytes` is already a leaf, so even the current shape is safe; the hazard would only arise from a future *transparent lazy collection*, which the scope statement forbids.)
- durable graph containing a callable **spec** — pure B data (tagged maps); certification true; barrier-inert end to end. A spec never contains a live closure by construction (rule §3).
- `{:data durable-handle :handler live-closure}` — same as the first: O(2 + closure).

Answers to the nine questions:
1. **Yes — opaque by the leaf rule**, and this must be structural, not special-cased: the transforms match exhaustively on `Val`; every non-container arm is a leaf. A new variant forces an explicit arm — a future `DurableHandle` is born inert (this is required abstraction change 1, §11).
2/3. **A durable collection cannot contain a live closure and remain durable** — it fails certification and is simply a local (A-contaminated) collection. Nothing breaks; it just loses B privileges (hashing, transfer, spec embedding). Same semantics as cap-freeness.
4. **Yes** — a local collection references a huge durable graph through its handle without traversal; that is the entire point of the leaf rule.
5. **Durability eligibility = construction-time certification, surfaced through summary bits.** Not a type split yet (PR-2 may add one); not a use-time recursive predicate (O(N) per check); the encoded representation is the *consequence* of certification, not the test. Precedents: Monte DeepFrozen (proof at construction), Chez stability classes, and Glia's own has-resting-refs flag. Stage one: binding-granularity flag (implemented in spike); PR-2: per-node bit maintained compositionally (bit = OR of children) so certification is O(1) at every construction.
6. **Durable values carry only descriptors (C), never live remote capabilities.** A live remote cap is a `Cap` (A) whose transport is Wetware RPC, not value serialization. Its durable form is a descriptor the receiving side must *resolve through its own authority* — anything else mints authority from data.
7. **No conflation today** — the equality audit (§2) shows structural-vs-identity already tracks the domain line. The rule to preserve: content-hash identity is defined only for certified-B values (where structural equality and content equality coincide); local identities (env ptr, cap id, atom ptr) must never leak into durable identity or encodings.
8. **PR-2 needs the summary-bit discipline; it may or may not need a distinct durable collection type.** The bit is REQUIRED (it serves both the barrier and certification); a separate type is a PR-2-time decision. Recorded as a PR-2 input, not a PR-1b.0 blocker.
9. **The exact O(N)-prevention rule** (two halves): (a) the leaf rule above — traversal never crosses a non-container variant; (b) the summary discipline — a container whose contains-A bit is false is itself a leaf. Stage one approximates (b) at binding granularity: one O(N) walk at `define` per *materialized in-RAM* value, O(1) reads thereafter for data-only bindings. That is acceptable for values that already cost O(N) to build in RAM, and the scope statement's handle rule guarantees no walk can ever force a lazy fetch. Full (b) lands with PR-2 collection bits.

## 5. Memory-model comparison (A–D)

*(GC-precedent evidence from the four source studies integrates here; the structural analysis below is complete and the agent findings adjust confidence, not shape.)*

### A. Amended Graph 4 (Rc/Weak + ownership barrier)
Proven by spike + preflight. Deterministic drop; zero GC infrastructure; trivially WASM; capability release timing exact. Costs: the barrier (rest/escape + capture normalization + defcap sealing + witness discipline ≈ 400–500 lines of genuinely disposable mechanism), O(value) upgrading reads with sharing loss, the accepted atom-cycle leak class, and per-type vigilance (every new A-variant must be classified against the ledger).

### B. Closure/environment-only tracing arena
Would remove: deep value rewriting, capture normalization, defcap cycle special-casing, foreign-owner transitions, and the atom-closure leak class (cycles become collectable) — i.e. *the entire barrier*. Would add: `Collect`/trace impls on every A-type; a root contract; write barriers on every mutation of traced state; and — the structural blocker found by this analysis — **the two-world reference problem**: `Val::Fn` is a *value inside ordinary Rust data*, so either (i) the arena brand lifetime (`Gc<'gc, T>`) infects `Val` itself and therefore every signature in the workspace, or (ii) callables become handle indices with a side-table root registry, reintroducing exactly the escape/root bookkeeping the arena was meant to remove, plus (iii) Glia's evaluator is **async** (effects suspend across `await`) and arena pointers cannot be held across await points — the evaluator would need total restructuring or unsafe rooting. gc-arena/Ruffle evidence (agent 2) quantifies (i) and (iii).

### C. Rc + cycle collection
Semantically cleanest (all references strong; no barrier; no weakness anywhere). Structural costs: participation is never free — CPython requires a per-object GC header plus `tp_traverse`/`tp_clear` on every container type; Rust equivalents replace the pointer type (`Cc<T>`). Glia-specific problems: (i) opaque host edges — `Rc<dyn Any>` cap inners, `Rc<dyn Fn>` native captures, and async machinery (oneshot senders holding `Val`s, boxed futures) hide edges from any tracer; hidden edges = permanently uncollectable cycles, and hosts *cannot* be forced to implement traverse over arbitrary captured state (it is our documented trust boundary); (ii) **capability nondeterminism** — cycle members drop when the collector runs, so authority release timing becomes collector-scheduled; the Drop-releases-only rule keeps this safe but makes release *observably late*; (iii) retrofit = replacing `Rc` across the value tree. Agent 4 quantifies the per-type contract and bug classes.

### D. Per-process tracing/generational heap (BEAM-adjacent)
**Best long-term semantic fit with Wetware, and the three-domain split is precisely its enabling precondition.** The BEAM correspondence is exact: per-process heap ↔ domain-A executable graph; off-heap refcounted binaries (never traced internally, O(1) per reference to the collector) ↔ CID-backed durable data behind handles; literal areas ↔ the frozen prelude and closed module constants; message copying ↔ cross-process B-data transfer; funs-as-references across nodes ↔ durable callable specs; wholesale heap release at process death ↔ child-authority lifecycle cleanup. Costs: a real collector in Rust (moving or non-moving), pointer discipline at every native boundary, rooting API for embedders, and a magnitude comparable to the entire current runtime. Not stage-one under any reading; the architecture must merely not foreclose it. Agent 3 grounds the correspondence in source.

Answers:
1. **Yes — `OwnerRef` remains entirely private** (verified in the amended contract; gate item).
2. **Yes — `Defs` can become a traced object with zero semantic change**: its contract (late lookup, top-level interning, freeze, inheritance) never mentions memory.
3. **Yes — `CapturedEnv` can hold GC handles**: accessor-mediated, constructor-normalized already.
4. **No — collections must not know about `Rc`/`Weak`**: today they don't (they hold `Val` by value); the barrier rewrites *copies* rather than mutating in place, which is exactly why. Preserve under PR-2: the summary bit is the only ownership-adjacent thing a collection may carry.
5. **Yes, host APIs can remain memory-model-neutral** *except* the two public `Rc<dyn Fn>` aliases — acceptable stage-one debt; freeze the surface.
6. **Under GC, embedders would need a rooting API** — unavoidable in B/C/D; today's implicit "any Val you hold is alive" is an Rc property. Mitigation: keep the embedder surface small (it is: eval entry points + native registration), so the future rooting contract lands in few places.
7. **Deletion inventory**: cycle collection (C) deletes OwnerRef, both transforms, the flag, witness plumbing (≈400–500 lines by spike proportion) and adds traverse/clear everywhere; tracing arena (B) deletes the same plus `CapturedEnv` weakness and adds Collect + root plumbing + evaluator restructuring; full GC (D) deletes all of the above plus Rc layout throughout. In every case `Defs`, the top-level gate, `CapturedEnv`-as-split, exports, freeze, versioning, and the choke-point functions **survive**.
8. **Tests that survive migration**: the semantic halves of all 17 proofs (recursion works, exports outlive envs, attenuation transfers, identity/hash stability, callable map keys, module lifetime) — these become the language's conformance suite; the `strong_count`/leak-class assertions and transform laws (props 1–3) are RC-specific and die with the barrier. Worth doing at implementation time: tag each test `// SEMANTIC` vs `// RC-MECHANISM` so the migration inventory is mechanical (required change 6, §11).
9. **Docs**: `definition-ownership.md` must specify ownership/lifetime *semantics* (definitions own; escapees keep owners alive; module close freezes) with the RC barrier in a clearly-marked implementation section — drafts in §13.
10. **Proportionality: yes.** The knowingly-disposable fraction is ≈400–500 lines of mechanism (transforms + OwnerRef + flag) already de-risked by the spike; everything else PR-1b.0 builds (≈ the majority of +900/−350) is language semantics that survives every future model. Stage-one cost is proportionate even under a certain-migration assumption.

**Desired property** — *local owner management must never traverse the transitive contents of a huge durable/IPFS-backed graph* — **HOLDS under the §4 scope statement, and only under it.** Two obligations make it unconditional: (1) the leaf rule as a structural property of the transforms (exhaustive match; every non-container variant inert — already true in the spike); (2) the prohibition on transparent lazy collections — lazy/CID data enters only as an opaque handle. With those, no barrier operation, authority walk, or export can ever force or traverse durable content. Without them (i.e., if someone later added a transparent lazy `Map` backed by Bitswap), `rest_for` at `define` would fault-in an entire DAG — that is the one true dead-end path, and it is closed by rule, not by hope. Verdict input: **not NO-GO; GO conditional on the scope statement being adopted as normative** (§11 change 1).

## 9. Effect-system interaction

1. **Yes — effect requirements replace captured live authority in durable callables.** This is B3's import semantics generalized: authority is contextual (granted by the instantiator's handlers/caps), not intrinsic (baked into the value).
2. **Yes — it removes closure-serialization pressure almost entirely**: the only closures worth making durable are the authority-free-modulo-requirements ones, which is exactly what the §3 rule certifies.
3. **Yes — deterministic handlers give reproducible execution**: same spec + same handler responses = same result; the effect transcript is the replay log (and the future basis for durable-object state replay in Wetware).
4. **Yes — content fetching is already capability-shaped**: `ModuleLoader` behind the import cap is the loader capability; a `:glia.fetch`-style effect (or a fetch cap) is the same pattern for data. No ambient IPFS access, ever.
5. **Effect requirements should be declarative metadata on the spec** (C-domain data), *checked* against discovered analysis at instantiation. Declared-but-unused: harmless. Used-but-undeclared: instantiation-time catchable error. Runtime-only discovery alone is insufficient for durable specs (the instantiator must know what to grant before running).
6. **Live authority analysis covers possession only** — what a value *holds* (captures, cap fields). Installed handlers are *contextual* authority: granted at call/instantiation time, governed by grant policy, not by value analysis. Keeping these two ledgers separate is the same discipline as keeping OwnerRef out of authority semantics.
7. **Yes — the handler stack is entirely local runtime heap** (A-domain machine state; never a value; never serialized).
8. **No effect-system state needs durable representation now.** (Future: effect *transcripts* for replay — durable B data, but that is Wetware-side work.)
9. **Yes — Graph 4 sees effect handlers only as local executable values** (handler closures stored by the with-effect-handler machine are escaped-strong per the storage audit; the machine itself is not a Val).
10. **Security risk exists and is already correctly shaped**: fetched/imported code runs with the *importer's* handler stack by explicit B3 decision — import is an act of granting. The risk is importer over-grant, not ambient inheritance; the mitigation path (attenuated import: shrink the handler stack / cap set passed to an instantiation) is future work aligned with the child-bootstrap grants design, and durable specs' declared requirements (answer 5) give the instantiator the information to grant minimally.

**Portability/authority rule (adopted):**

> Durable values carry *descriptions* of authority — requirements, capability descriptors, module references — never authority itself. All authority is granted locally, at instantiation or call time, through capabilities and effect handlers, which are local executable values that never serialize. Fetched or imported code therefore executes with exactly the authority its local instantiator grants it, and a durable value's meaning is independent of every process-local pointer, handler stack, and memory-management state.

## 10. Revised PR-1b.0 implementation gate

PR-1b.0 implementation may begin only when ALL hold:

1. The §4 jurisdiction statement is adopted as normative: Graph 4 confined to local executable graphs; every domain-B value and opaque payload barrier-inert.
2. The transforms are written as exhaustive `Val` matches where every non-container arm is a leaf — adding a `Val` variant must force a compile-visible classification decision.
3. Local handles/leaves to huge durable data are O(1) to rest/escape (structural consequence of 2; test required).
4. Memory-lifetime semantics are not guest-visible: no guest program can distinguish weak/strong states except via the documented internal-fault channel; `glia.error/*` categories never name ownership mechanics.
5. `OwnerRef`, weak states, and both transforms remain crate-private — no public signature, error text, or doc exposure.
6. Host APIs do not grow their `Rc`-pinned surface (the two existing native aliases are frozen debt, documented as migration hazards).
7. Future tracing/cycle collection remains possible: the five choke points stay named functions; tests are tagged SEMANTIC vs RC-MECHANISM; the §7 deletion inventory is recorded in the design doc.
8. Authority semantics have zero dependence on pointer strength (preflight normative rule; re-asserted as a gate check with the two-ledger separation of §9.6).
9. No intended workload from §8 incurs whole-DAG traversal (workloads 1, 4, 5 get regression tests at implementation time).
10. Disposability check passes: the RC-specific fraction stays in the few-hundred-line range established by the spike; if implementation discovers the barrier metastasizing beyond the five choke points, stop and re-run this decision.

## 6. GC precedent findings (source-pinned; full records in `.context/preflight-studies/batch6..9-*.md`)

### Boa GC (batch6) — Rust dynamic-runtime tracing GC, pinned 4fc75c6a
Thread-local, non-moving, stop-the-world mark-sweep over individually-boxed `GcBox{header: 2×u32, vtable, value}`; **no rooting API and no stack scanning** — at collect time a full-heap pass counts in-heap handles (`non_root_count`) and an object is a root iff `non_root_count < ref_count` (some handle lives outside the heap). Ephemeron-based weak refs with fixpoint semantics; Mark→Finalize→re-Mark→Sweep because finalizers may resurrect.
**What Glia could borrow:** (1) the rooting-by-subtraction trick — it composes exactly with Rc-shaped handles and would make escape detection *automatic at collect time* instead of maintained at mutation time (the strongest ingredient for a future option-C/B root discovery); (2) the partition precedent — only the cyclic `JsObject` graph is traced; `JsString`/`JsBigInt`/`JsSymbol`/source text are plain Rc/Arc/interned with `empty_trace`, and Boa has repeatedly *migrated data out of* the traced heap (CompileTimeEnvironment PR #3025, SourceText #4293) — direct working precedent for "trace executables only, keep immutable data Rust-owned"; (3) iterative tracer (their recursive one hit a real stack overflow, #1848 — mirrors our iterative-transform decision); (4) derive-forced `Drop` prohibition.
**What does not transfer:** rooting-by-subtraction requires TOTAL conversion — every internal reference to a traced object must itself live inside a traced box, or roots are misclassified (a half-converted Glia is unsound, not degraded); O(entire heap) pause on every collection (two full walks), no generations, no incrementality; `thread_local!` singleton heap is the opposite of process isolation (their issue #5186); finalizers receive `&self` and can resurrect — an ambient-authority hazard a capability runtime must design out (confirms our Drop-releases-only rule from the opposite direction).
**Complexity ledger:** 3,542 LOC core + 145 derive; **178 unsafe tokens** (86 blocks / 44 unsafe fn / 36 unsafe impl), 118 SAFETY comments; production bug classes: root-count overflow → `is_rooted()==false` on live objects → UAF (#4936/#4950/#4951), finalizer reentrancy panic (#5337), threshold truncation (#4701), trace-recursion overflow (#1848), sweep raw-fn-pointer ACE surface (#5187). Native closures are the wart: safe API only for `Copy` closures; capturing closures go through an `unsafe fn` citing rust-gc#50 — **exactly Glia's native-capture trust boundary, confirmed as the universal sore spot**. WASM: works unchanged (single-threaded by construction). Confidence: high.

### CPython cycle collector + bacon-rajan-cc (batch7) — option C ground truth, pinned 5918085b / v3.11.9 / e8f6ff5f
CPython: every collectable object gets a two-word `PyGC_Head` **prepended by the allocator**; types implement the two-function contract (`tp_traverse` enumerates strong edges exactly; `tp_clear` breaks them); collection is trial deletion over a generation (copy refcounts → subtract internal edges via traverse → residual >0 = externally rooted) — **no root scanning ever**: host-held references are roots automatically. Six lifecycle obligations per container type; correctness is a *whole-system* proof ("Taken together, all tp_clear functions in the system must combine to break all reference cycles. This is subtle…"). Twenty years of scar tissue at exactly Glia's boundaries: missing traverse → weakref callback runs on cleared objects → crash (bpo-38006/gh-91636); still-tracked during teardown → double-free; untracked containers in cycles → permanent leaks; tuning heuristics repeatedly added then *removed* when mutator cost exceeded GC savings (GH-127010).
bacon-rajan-cc: the Rust shape of option C — `Cc<T: Trace>` replaces `Rc<T>` (box carries `buffered` + `color`), decrement hook buffers possible roots, explicit `collect_cycles()` does Bacon-Rajan trial deletion over *suspects only* (no heap registry, no generation scans). Materially cheaper per type than CPython (one `Trace` impl vs six obligations). Its own test suite contains **literally Glia's shape** — `Env { closures: Vec<Cc<RefCell<Clos>>>, next: Option<Cc<Env>> }` / `Clos { env: Cc<Env> }` — with an in-tree comment recording the historical premature-free bug. Unmaintained since 2023-10 (fork/study, don't depend); single-threaded and wasm-clean; `RefCell` borrowed at collect time = panic → collection only at eval-loop safepoints.
**Synthesis (a)** — *retrofit onto `std::rc::Rc` is structurally impossible*: participation is decided at allocation time and lives in the pointer/box (header, color bits, decrement hook); and with plain `Rc` you cannot break a discovered cycle at all — every strong edge would need `RefCell<Option<…>>` severability, a bigger type perturbation than the barrier it replaces. Option C therefore means a `Cc`-shaped pointer migration, total within the participating graph.
**Synthesis (b)** — *opaque host objects cannot participate without hand-written traverse*, and hidden edges fail silently as leaks and loudly as crashes at the weakref/teardown boundary (CPython's documented failure class). Native closures either get compiler-forced `Trace` (supertrait) or are structurally barred from owning participating values — "trust the host not to form cycles" is exactly CPython's untracked-container rule, with its exact failure history.
**Synthesis (c)** — both models are single-threaded/WASM-clean; the care point is traversal recursion depth (worklist needed — mirrors our iterative-transform rule).

### BEAM/ERTS (batch8) — option D destination architecture, pinned d459618c
Per-process contiguous heap+stack; two-generation copying GC with a high-water mark and **no write barriers or card tables — the old→young pointer prohibition "comes naturally… because the terms are immutable"**. Explicit tiny rootset (stack, registers, process dictionary, a handful of named cells, message queue). Message send = deep copy into the receiver's heap; **two exceptions bypass copying and tracing entirely**: (1) literals — module constants in one reserved 1 GB address region, recognized by a two-pointer range check (`erts_is_literal`), never copied, never scanned; purge = make each referencing process copy them in, then free the area once; (2) off-heap binaries >64 bytes — refcounted `Binary` objects; the heap holds a tiny `BinRef` node threaded on the per-process off-heap list; copy = refc++, GC = list sweep + refc−−, **contents never traced (O(1) per reference regardless of size)**; a "virtual binary heap" counter triggers GC on off-heap pressure. Process death: heap freed wholesale; only the off-heap list is walked for refcount drops. Funs cross nodes as `NEW_FUN_EXT` = module + index + 16-byte MD5 + free-variable *values* — never code, never pointers. NIF resources = refcounted opaque handles with destructors at refc-zero.
**What Glia borrows (mechanism → domain):** BinRef/off-heap list → CID durable handles (the §4 leaf rule is BEAM's off-heap discipline verbatim, one choke point at copy/`define`); literal areas + range check → frozen prelude/module constants (and the purge protocol → un-pinning a CAS root while borrowers live); vheap accounting → "pinned durable bytes" pressure metric (useful even under Rc today); immutable-once-published → generational GC without write barriers *if the executable graph keeps Glia's snapshot semantics*; wholesale heap release → child-process teardown; NEW_FUN_EXT/EXPORT_EXT → durable callable specs; NIF resources → host capability lifetime.
**What does not transfer:** SMP machinery (collapses to turn boundaries for us); the assumption that all heap data is *copyable* — Glia capabilities are not; the EXPORT_EXT name-don't-copy path must be the RULE for caps, not the exception. Complexity honestly recorded: fragments, move-markers, the ~40-line purge-protocol state machine, vheap growth heuristics.

### RustPython + gc-arena/Ruffle (batch9) — the negative and positive Rust-runtime results, pinned 9dff4d3a / ffc3821d / 5b6f6665
**RustPython (negative result for unmitigated Rc):** custom refcounted `PyInner<T>` objects; for ~7 years the `gc` module was a stub (`collect()` returned literal `0`) and cycles — including the module-dict→function→globals-dict shape RustPython demonstrably has (`PyFunction { globals: PyDictRef, … }`) — **leaked permanently**; open leak issues since 2020 (#2380, #3504); a stop-the-world collector PR (#4180) was rejected in 2024; in 2026-01 the project capitulated and shipped a full CPython-style backup cycle collector (#6910): per-object gc bits + intrusive generation lists + unsafe per-type `Traverse`/`clear` + STW safepoints. **The lesson: option C's end-state contains all of option B's tracing machinery *plus* refcount overhead and safepoint infrastructure.** Two direct Graph 4 analogues found in its design: `NEW_REF_UNTRACKED` (frames start GC-untracked, tracked only on escape — **the first production analogue of weak-at-rest/strong-on-escape**, upgrading Graph 4 from "precedent-free flip" to "independently reinvented discipline") and `clear()`-extract-children-then-drop-outside-locks (the manual cycle-breaking barrier shape).
**gc-arena/Ruffle (positive precedent for option B exactly as scoped):** one arena per player; `Gc<'gc, T>` branded by an invariant generative lifetime so pointers cannot escape `mutate()` — no rooting bugs by construction; safe derive with a compiler-enforced no-`Drop` rule; mutation only through `Gc::write` barriers; incremental debt-paced collection pumped once per frame tick. Ruffle's production root (`GcRootData`, ~24 fields) holds interpreters/display tree/closures/scope chains while **large immutable data stays outside** (`SwfSlice { movie: Arc<SwfMovie>, … }` inside traced objects via `require_static`) — the exact executables-in/data-out partition. `DynamicRootSet` ("handles to GC objects outside the GC") **subsumes OwnerRef's escape mechanism wholesale**: escaped callable = dynamic root, resting one = ordinary traced edge, no manual barrier. **The price is total and confirms the §5.B blocker:** the `'gc` brand rewrites every interpreter signature (`Activation<'a, 'gc: 'a>`, `Result<Value<'gc>, Error<'gc>>` everywhere); **no `Gc` may cross an `await`** — Ruffle's async loaders hold `Arc<Mutex<Player>>` + a plain slotmap key and re-enter the arena after every await; value `Drop` may not touch traced pointers (revocation must move to finalize-phase sweeps). Works on wasm32 (`#![no_std]`, threadless). Retrofit onto Glia's existing Rc/RefCell types is a whole-crate rewrite, not an increment.

## 1. Executive recommendation

**GO — GRAPH 4 AS STAGE ONE, WITH REQUIRED ABSTRACTION CHANGES** (the §10 gate). Classification against the four candidate outcomes: amended Graph 4 is **an acceptable, consciously transitional mechanism** — not a dead end, and not clean-stage-one-without-conditions. The durable-data constraint is satisfied *by rule, not by luck*: Graph 4 is confined to local executable graphs, every durable value is barrier-inert by the leaf rule, and the one true dead-end path (transparent lazy collections) is closed normatively. The future-GC constraint is satisfied by seams: everything PR-1b.0 builds except ~400–500 lines of barrier mechanism is language semantics that survives every studied memory model, and the studied destination (BEAM-style per-process heaps with off-heap durable data) *requires* the three-domain split this study adopts — stage one actively builds toward it. The four source studies sharpened rather than changed the picture: RustPython proves shipping Rc-without-cycle-handling at scale ends in capitulation (Glia's difference: the barrier prevents the routine cycle class up front, and the atom class is accepted, measured, and fenced); Ruffle proves the scoped tracing arena works but only as a greenfield architecture — its brand lifetime and no-Gc-across-await rules make it a rewrite, not a migration; CPython/bacon-rajan prove cycle collection cannot be retrofitted onto `std::rc::Rc` and is dominated anyway; BEAM proves the destination architecture and donates the durable-data mechanism (off-heap refcounted handles, never traced) that Graph 4's leaf rule implements today in miniature.

## 11. Required abstraction changes (all zero-or-near-zero implementation cost; conditions of the GO)

1. **Adopt the §4 jurisdiction statement as normative** (goes into `definition-ownership.md`): Graph 4 = local executable graphs only; durable values bypass by the leaf rule.
2. **Structural leaf rule**: transforms are exhaustive `Val` matches; every non-container arm is a leaf; a new variant forces a compile-visible classification. (Already true in the spike; becomes a stated invariant.)
3. **No transparent lazy collections, ever**: lazy/CID-backed data enters only as an opaque handle behind an explicit materialization capability/effect.
4. **Choke points stay named functions** (define / lookup / for_call / cap dispatch / export) — the future write-barrier or root-transition sites under any GC.
5. **`OwnerRef` and weak states strictly crate-private** — no public signature, error text, Debug output, or doc exposure; guest-visible semantics never mention memory (gate items 4–5).
6. **Freeze the public Rc surface of host APIs** (`NativeFnImpl`/`AsyncNativeFnImpl` stay as-is, documented as migration hazards; no new public Rc aliases).
7. **Test taxonomy**: every PR-1b.0 test tagged SEMANTIC vs RC-MECHANISM; the §7 deletion inventory recorded in the design doc.
8. **Durable identity never derived from local pointer identity**; content hashing defined only over certified-B values.
9. **Three regression tests** from §8: (a) barrier ops on a local value holding a large `Bytes`/opaque payload are O(local nodes); (b) export map with mixed fns + large leaves walks only fns; (c) define/lookup of a deep pure-data binding takes the flag fast path.

## 15. Final verdict

**GO — GRAPH 4 WITH REQUIRED ABSTRACTION CHANGES** (§11; equivalently: GRAPH 4 AS STAGE ONE conditioned on the §10 gate).
